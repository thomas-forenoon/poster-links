Methods

This page describes the method configuration used to reproduce the poster result regime.

1) Scope and code path

The results were reproduced using the dedicated poster analysis notebooks for graph splitting and modelling, together with a runner script for the poster matrix. Inputs were seeded from the baseline processed and exploratory data analysis artefacts, and outputs were written to a separate reproduction directory to avoid conflict with the current setup.

2) Objective and label definition

This task is not positive–unlabelled learning.

Binary supervision is defined on observed FAERS pairs:

  • y = 1: FAERS signal (is_signal = True) with a minimum support threshold
  • y = 0: FAERS non-signal (is_signal = False) with a minimum support threshold

So this is FAERS signal classification for the poster task, not cross-source discovery labelling.

2.1 Exact FAERS signal rule

In the exploratory data analysis stage, the FAERS signal flag is computed as:

is_signal = (q_fdr < 0.05) AND (ROR > 2.0) AND (a >= 5)

where:

  • a = number of unique FAERS cases for the (drug_key, event_key) pair
  • q_fdr = Benjamini–Hochberg FDR-adjusted p-value from the 2×2 table chi-square test
  • ROR = reporting odds ratio computed with continuity correction (cc = 0.5)

Training labels are then formed as:

  • positives: is_signal = True and a >= MIN_A_FOR_POS (default 5)
  • negatives: is_signal = False and a >= MIN_A_FOR_NEG (default 5)
  • class ratio control: NEG_POS_RATIO (default 1.0)

3) Data and candidate construction

Inputs come from processed, harmonised artefacts across SIDER, OFFSIDES and FAERS.

Label construction uses FAERS disproportionality outputs:

  • Positives: FAERS-signalled pairs
  • Negative pool: FAERS-observed non-signals
  • Default balancing: NEG_POS_RATIO = 1.0 (approximately balanced classes)

4) Splits

The notebooks generate:

  • trans (edge-level random split)
  • entity (drug holdout)
  • time (year-based split)

For the reproduced table below, evaluation uses split = trans.

5) Graph and feature variants

Compared configurations:

  • so_flags = no FAERS base graph + flags-only edge features
  • so_full = no FAERS base graph + full edge features
  • sof_flags = FAERS base graph + flags-only edge features
  • sof_full = FAERS base graph + full edge features

Leakage control for this task:

  • Keep non-FAERS label-side statistics out of x_edge where configured
  • Core comparisons are between graph connectivity and OFFSIDES-derived evidence profiles

5.1 Operational leakage control statement

The label source in this task is FAERS disproportionality (the is_signal rule above). To avoid direct label-source leakage into training covariates, the edge-feature schema excludes FAERS-derived signal predictors.

Excluded from x_edge:

  • in_faers
  • all faers_* columns, including faers_a, faers_drug_tot, faers_event_tot, faers_ror, faers_prr, faers_ic, faers_p and faers_q_fdr
  • the direct signal flag (is_signal) and transforms derived from FAERS signal statistics

Allowed in x_edge (full and flags profiles):

  • source indicators from the non-label source: in_sider, in_offsides
  • OFFSIDES statistics: offsides_A, offsides_PRR and log1p transforms (for full features)

5.2 Leakage audit mechanism

Hard assertions are executed before bundle export:

assert not any(c.startswith("faers_") for c in edge_feature_cols) assert "in_faers" not in edge_feature_cols

In addition, a feature manifest is written per run with:

  • allowed_edge_features
  • forbidden_patterns = ["faers_*", "in_faers"]

This provides an auditable schema-level check that FAERS disproportionality predictors derived from the label source are not part of the training edge features.

5.3 Residual co-occurrence information

For sof_* variants, FAERS edges are present in graph topology (message-passing adjacency). This carries observational co-occurrence structure by design, but not direct inclusion of the FAERS signal-rule statistics in x_edge.

Interpretation of adjacency contribution is handled through ablations:

  • so_* (no FAERS base graph)
  • sof_* (with FAERS base graph)

6) Models and metrics

Models:

  • Edge-only baseline (EdgeMLP on x_edge)
  • Heterogeneous GNN (graph-aware model)

Reported metrics:

  • AUROC
  • AUPR
  • ECE
  • Brier
  • Uncertainty on safe / unknown (mean MC-dropout predictive entropy by class)

Uncertainty semantics:

  • safe = y = 0 (FAERS non-signal)
  • unknown = y = 1 (FAERS signal)

6.1 Reviewer-facing wording

For manuscripts and posters, prefer leakage-controlled or schema-audited leakage control over an unqualified leakage-safe claim, unless the concrete exclusions and audit checks listed above are shown alongside it.
