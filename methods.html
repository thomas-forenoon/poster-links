ADE Discovery Methods

This document describes the experiment in plain language for readers who do not need code access.

1) What this poster is trying to answer

The task in this experiment is a control task:

  • Given a drug-event pair, predict whether it is a FAERS signal pair or a FAERS non-signal pair.

This is not yet a PU-learning framework aimed at discovering unobserved pairs. Rather, it is a supervised classification task conducted on observed FAERS pairs to provide deeper insight into the structure and characteristics of the data that will form the basis of the full dissertation.

2) Data used

We combine three sources:

  • FAERS: spontaneous adverse-event reports (Banda et al., 2016)
  • OFFSIDES: side-effect evidence from a separate source (Tatonetti et al., 2012)
  • SIDER: known side effects from labels (Kuhn et al., 2016)

3) How labels were defined (exact rule)

A drug-event pair was labelled as a positive signal if all of the following were true (van Puijenbroek et al., 2002; Benjamini and Hochberg, 1995):

  • ROR > 2.0
  • q_fdr < 0.05
  • a >= 5 reports

In short:

  • Positive class (y=1): statistically strong FAERS signal with enough support
  • Negative class (y=0): observed in FAERS but does not meet the signal rule, with enough support

Quick definitions:

  • ROR (Reporting Odds Ratio): effect size for disproportionality (van Puijenbroek et al., 2002)
  • q_fdr: multiple-testing-corrected p-value (Benjamini and Hochberg, 1995)
  • a: number of FAERS cases for that drug-event pair

Class sampling in this setup used roughly a 1:1 negative-to-positive ratio.

4) Leakage control (what was removed and how it was checked)

Leakage means the model could “peek” at variables that directly encode the target rule (Kaufman et al., 2012).

To control leakage, we removed all label-source-derived disproportionality features (for example FAERS signal statistics and direct signal flags) from training inputs, and retained only graph topology and non-label-source covariates.

To prevent that, we removed all FAERS signal-rule-derived predictors from training inputs (Kaufman et al., 2012), including:

  • FAERS disproportionality statistics (for example ROR/PRR/IC, p-values, adjusted p-values)
  • FAERS report-count style predictors used by the signal rule
  • Direct FAERS signal indicators

We kept:

  • Graph structure (which entities are connected)
  • Non-label-source covariates from OFFSIDES and SIDER

Leakage audit:

  • Before training, schema checks rejected forbidden FAERS signal-rule feature patterns.
  • Feature manifests were exported so the final input schema was auditable.

Important limitation to state clearly:

  • In configurations that include a FAERS graph, FAERS co-reporting structure still contributes through graph topology.
  • This is not the same as feeding FAERS signal-rule statistics directly as features (Kaufman et al., 2012).

5) Model configurations compared

We evaluated five configurations:

  1. Edge-only baseline (full features): no graph message passing
  2. Graph + full features
  3. Graph + flags only (remove numeric OFFSIDES evidence values)
  4. No FAERS graph + full features
  5. No FAERS graph + flags only

6) Metrics reported

  • AUROC: ranking quality across thresholds (Fawcett, 2006)
  • AUPR: precision-recall quality (important with class imbalance) (Davis and Goadrich, 2006)
  • ECE: calibration error (lower is better) (Guo et al., 2017)
  • Brier score: probabilistic accuracy/calibration score (lower is better) (Brier, 1950)
  • Uncertainty on safe: mean predictive entropy for y=0 (non-signal) pairs (Gal and Ghahramani, 2016)
  • Uncertainty on unknown: mean predictive entropy for y=1 (signal) pairs (Gal and Ghahramani, 2016)

Interpretation:

  • Graph models clearly outperform the edge-only baseline.
  • Removing FAERS graph edges lowers performance, showing topology contribution.
  • In this setup, full vs flags-only differences are small compared with graph/no-graph differences.
