Methods

This page summarises the method configuration used to reproduce the poster results.

1) Scope and code path

The poster results were reproduced through an internal notebook pipeline for graph splitting and modelling, with a dedicated runner script used to generate isolated outputs. Processed and exploratory inputs were seeded from a baseline run, and reproduction outputs were written to a separate location to avoid conflict with the current setup.

2) Objective and labelling

This task is a binary FAERS signal classification task and is not positive–unlabelled learning.

  • y = 1: FAERS signal (is_signal=True) with a minimum support threshold
  • y = 0: FAERS non-signal (is_signal=False) with a minimum support threshold

The target therefore reflects FAERS signal status for observed drug–event pairs, rather than cross-source discovery labels.

2.1 Exact FAERS signal rule

is_signal = (q_fdr < 0.05) AND (ROR > 2.0) AND (a >= 5)

  • a = number of unique FAERS cases for the (drug_key, event_key) pair
  • q_fdr = Benjamini–Hochberg FDR-adjusted p-value from the 2×2 table chi-square test
  • ROR = reporting odds ratio computed with continuity correction (cc = 0.5)

Training labels were then formed as follows:

  • Positives: is_signal=True and a >= 5
  • Negatives: is_signal=False and a >= 5
  • Class ratio control: NEG_POS_RATIO = 1.0 by default

3) Data and candidate construction

Inputs were drawn from processed, harmonised artefacts spanning SIDER, OFFSIDES and FAERS. Label construction used FAERS disproportionality outputs:

  • Positive class: FAERS-signalled pairs
  • Negative pool: FAERS-observed non-signals
  • Default balancing: approximately balanced classes (NEG_POS_RATIO = 1.0)

4) Splits

Three evaluation splits were generated:

  • trans – edge-level random split
  • entity – drug holdout
  • time – year-based split

The poster results shown here use split = trans.

5) Graph and feature variants

Four configurations were compared:

  • so_flags – no FAERS base graph + flags-only edge features
  • so_full – no FAERS base graph + full edge features
  • sof_flags – FAERS base graph + flags-only edge features
  • sof_full – FAERS base graph + full edge features

Core comparisons are between graph connectivity and OFFSIDES-derived evidence profiles, while keeping label-side FAERS statistics out of edge features where required.

5.1 Leakage control statement

The label source in this task is FAERS disproportionality. To avoid direct label-source leakage into training covariates, the edge-feature schema excludes FAERS-derived signal predictors.

Excluded from x_edge:

  • in_faers
  • All faers_* columns, including: faers_a, faers_drug_tot, faers_event_tot, faers_ror, faers_prr, faers_ic, faers_p, faers_q_fdr
  • Direct signal flags such as is_signal and transforms derived from FAERS signal statistics

Allowed in x_edge:

  • Non-label source indicators: in_sider, in_offsides
  • OFFSIDES statistics: offsides_A, offsides_PRR, and log1p transforms for full profiles

5.2 Leakage audit mechanism

Before export, hard assertions were applied to verify that FAERS-derived predictors were absent from the edge-feature schema:

assert not any(c.startswith("faers_") for c in edge_feature_cols)

assert "in_faers" not in edge_feature_cols

A feature manifest was also written per run, recording:

  • allowed_edge_features
  • forbidden_patterns = ["faers_*", "in_faers"]

This provides an auditable schema-level check that FAERS disproportionality predictors are not part of training edge features.

5.3 Residual co-occurrence information

In sof_* variants, FAERS edges remain present in the graph topology used for message passing. This retains observational co-occurrence structure by design, while still excluding the direct FAERS signal rule statistics from x_edge.

The contribution of adjacency is therefore interpreted through ablations: so_* (no FAERS base graph) versus sof_* (with FAERS base graph).

6) Models and metrics

Models compared:

  • Edge-only baseline (EdgeMLP on x_edge)
  • Heterogeneous GNN (graph-aware model)

Reported metrics:

  • AUROC
  • AUPR
  • ECE
  • Brier score
  • Uncertainty on safe / unknown (mean MC-dropout predictive entropy by class)

Uncertainty semantics:

  • safe = y = 0 (FAERS non-signal)
  • unknown = y = 1 (FAERS signal)
For reviewer-facing wording, leakage-controlled or schema-audited leakage control is preferable to an unqualified “leakage-safe” claim unless the concrete exclusions and audit checks above are presented alongside it.

6.1 RQ2 uncertainty-method ablation

To address RQ2 directly, calibration and accuracy metrics were computed on the same trained model and test split using:

  • a deterministic head
  • MC-dropout predictive mean

On this control task, MC-dropout was useful for uncertainty probing, but calibration gains were mixed rather than consistently improved.

Recommended wording: MC-dropout was used to quantify predictive uncertainty on the control task; deterministic-versus-MC calibration differences were mixed in this setup.
